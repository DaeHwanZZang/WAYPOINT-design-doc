7. API 설계

7.1 서버/클라이언트 구조

FMS의 외부 인터페이스는 세 갈래다. ① 웹 화면·외부 시스템과는 REST + WebSocket(HTTP JSON), ② 로봇·승강기·자동문과는 MQTT(Mosquitto 경유, JSON), ③ 로봇의 맵 다운로드는 HTTP 파일(맵 번들 zip)이다. 내부 모듈끼리는 같은 프로세스의 함수 API로, 학습 파이프라인과는 파일 API(운행 폴더·데이터셋·모델 폴더)로 연결된다.

7.2 서비스 REST API 정의

기본 경로 /api/v1, 요청·응답은 JSON(맵 업로드는 multipart). 인증이 켜지면 Authorization: Bearer <API 키>(WebSocket·이미지는 ?api_key=). 오류 규약: 도메인 예외 *NotFound → 404, *Error → 422, 버전·상태 충돌 → 409, 인증 401, 권한 403. 응답 본문 오류는 {"detail": "메시지"}. 아래 표는 FMS OpenAPI(2026-11-25)에서 생성했다. 대화형 문서는 서버의 /docs.

권한 매트릭스

역할은 viewer(조회) ⊂ operator(조작) ⊂ admin(관리) 포함 관계다. 아래 표는 구현된 82개 API 가 그룹별로 어느 역할부터 허용되는지를 OpenAPI 에서 자동으로 센 것이다. "기타(토큰)"는 로봇이 맵 번들을 받는 경로(API-109·110)로, API 키 대신 로봇 번들 토큰(FMS_ROBOT_TOKEN) 또는 ?api_key= 로 인증한다.

<표 7.10> API 그룹 × 최소 역할 (구현 82개, 칸 = API 수)

규칙은 세 줄이다. ① 읽기(GET)는 viewer. ② 로봇·작업·맵·설정을 바꾸는 쓰기는 operator. ③ 접근 권한을 만들거나 외부로 데이터를 내보내는 기능(API 키, webhook)과 현장 통째 삭제는 admin. 이번 개발 API 는 같은 규칙을 따른다: 운행 시작·종료(API-1001·1002)와 교통 정책 변경은 operator, AI 모델 다시 읽기(API-1006)는 admin, 나머지 조회는 viewer.

7.3 서비스 REST API 설계

구현된 각 API의 파라미터·요청·응답 필드다. 타입 뒤 ?는 null 허용, X[]는 배열. 응답의 중첩 모델(예: JobOut, RobotView)은 같은 이름의 스키마를 따른다.

7.4 AI학습서버 · AI 모듈 API 설계

학습은 FMS 밖에서 파일로만 주고받으므로(6.4절) 학습 서버에 별도 REST 서버를 두지 않는다. AI의 서비스 인터페이스는 FMS 프로세스 안의 ai_adapter 함수 API와, 그것을 관리·관측하는 REST API 두 층이다.
