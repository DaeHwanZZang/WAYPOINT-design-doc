용어뜻
AMRAutonomous Mobile Robot. 바닥 선 없이 센서와 지도로 스스로 길을 찾는 운반 로봇
FMSFleet Management System. 여러 로봇에 일을 나누고 통행을 조율하는 중앙 관제
점유 존교차로·좁은 통로처럼 한 번에 한 대만 지나야 하는 구역. 방향별 대기 node 와 출구 node 를 가진다
대기 node / 출구 node존 앞에서 허가를 기다리는 지점 / 존을 빠져나온 뒤 통과를 확인하는 지점
통행권 (released)오더 노드 중 로봇이 가도 되는 구간. 허가 안 된 노드 앞에서 로봇은 스스로 멈춘다 (VDA 5050 base/horizon)
order_update_id같은 오더를 재발행할 때 올리는 번호. 로봇은 자기 값보다 큰 것만 받아 통행권이 되돌려지지 않는다
층 정원한 맵(층)에서 동시에 이동 허가를 가질 수 있는 로봇 수
LWTLast Will and Testament. 로봇이 비정상 종료되면 브로커가 대신 보내는 연결 끊김 메시지
STALE / LOSTState 가 3초 이상 안 옴 / 연결 끊김 보고
wait-for 그래프"A 가 B 가 가진 자원을 기다림" 간선으로 만든 그래프. 순환이 있으면 교착
stall (정체)이동 중인데 60초 동안 0.3 m 도 못 가거나 통행 대기가 180초를 넘은 상태
시스템 작업FMS 가 스스로 만드는 작업: 충전(charge)·대기 복귀(staging)·대피(evacuation)·복구(recover)
예약 수 규칙(대기열 + 예약된 통과 수) × 평균 통과 시간으로 존 대기를 추정하는 기준선 (조건 ③)
운행 (run)실험 1회(15분). run_id 로 이벤트·State·메타를 묶는다
model_card모델 파일과 함께 두는 JSON. 특징·지표·데이터셋 해시·채택 여부
ai_adapterFMS 프로세스 안에서 모델을 읽고 추론하며 실패 시 규칙 값으로 대체하는 모듈
예약 (lease)FMS 장부(traffic.json)에 적는 자원 점유 기록. floor·wait·zone 세 종류. 로봇에 보내는 통행권(released)보다 먼저 저장하고, 새 State 의 증거로만 지운다
fresh로봇이 ONLINE 이고 위치 추정이 LOCALIZED 인 상태. 같은 맵에 fresh 가 아닌 로봇이 있으면 신규 존 진입을 허가하지 않는다
greedy 배정작업을 우선순위 순으로 하나씩 보며 그 순간 가장 싼 로봇을 고르는 방식. 전체 최적 할당(헝가리안)은 쓰지 않는다 (6.6.1)
ZonePlanner출발·목적지·대기/출구 node 로 만든 작은 그래프에서 어느 존을 어느 방향으로 지날지 고르는 FMS 쪽 계획기. 실제 주행 경로는 로봇이 계획한다 (6.6.2)
