실험 맵 synth3 설계 (제안)

본 실험의 지도는 "주 통로 1개 + 우회 통로 2개"로, 관제 방식에 따른 차이가 병목에서만 생기도록 일부러 단순하게 만든다. 아직 AMR-simulator 에 없는 맵이라 레이아웃을 여기서 정하고, 시뮬레이터의 맵 생성기(tools/synth_map.py, 한 글자 = 1 m)로 만든다. 배치 확정은 부록 A.5 #5 항목이다.

        …

<표 3.3> synth3 의 점유 존·node·작업 지점 (좌표는 레이아웃 칸 기준 개략값, 생성 후 맵 좌표로 확정)

이름종류위치(개략, m)설계 이유
Z1 주 통로점유 존x 8~32, y 9.5~11.5서↔동 최단 경로. 1대 폭이라 양방향이 같은 존을 나눠 쓴다(교착의 원인 장면)
Z2 / Z3 우회 통로점유 존y 0 / y 20 줄, 길이 24 m주 경로보다 약 1.6배 길다(34 m vs 53 m). 붐빌 때만 이득이 되는 길이로 잡았다
Zn-서대기 / Zn-동대기대기 node (waypoint)통로 축, 존 끝에서 1.4 m 바깥존 경계 + 차체 반경(0.53 m) + 여유. 서→동은 서대기, 동→서는 동대기에서 허가를 기다린다
Zn-서출구 / Zn-동출구출구 node (waypoint)통로 축에서 2 m 비켜난 작업 구역 안대기 node 와 다른 점에 둔다. 같은 점을 쓰면 서대기에서 기다리는 로봇(동→서 출구 자리)과 동대기에서 기다리는 로봇(서→동 출구 자리)이 서로의 출구 공간을 기다려 교착한다
W-01~05 / E-01~05작업 지점 (station)x 2 / x 38, y 2·6·10·14·18통로 세 개에 고르게 가깝게. W-03·E-03 이 주 통로 정면이라 붐빔 패턴의 출발·도착점
P-W1~3 / P-E1~3주차 (parking)작업 구역 바깥쪽 모서리대기 복귀·비켜주기 자리. 통로 입구를 막지 않는 곳
C-W / C-E충전기 (charger)작업 구역 안쪽 벽15분 운행에서는 거의 안 쓴다(시작 잔량 55~95%). 배터리 예측 데이터용
맵 설계 규칙 (synth3 에서 찾은 교착 패턴)양방향 통로의 한쪽 끝에서 "서→동 대기 node"와 "동→서 출구 node"를 같은 자리에 두면, 양쪽에서 동시에 기다리는 두 로봇이 각자 상대의 자리를 출구로 요구한다. FMS 는 출구 공간이 비어야 진입을 허가하므로(표 6.9) 둘 다 영원히 기다린다. wait-for 그래프에는 "점유 존 진입 허가 대기 → 출구 자리의 로봇" 간선이 생기지 않아(표 6.11 은 존 안 로봇·존 예약만 본다) 교착으로도 감지되지 않고 180초 뒤 정체로만 보인다. 따라서 ① 맵 규칙으로 대기·출구 node 를 분리하고(SC-07 저장 시 검사 추가, 계획), ② wait-for 간선에 "출구 공간을 막은 로봇"을 추가한다(wait_graph 보완, 계획). 두 항목은 부록 A.4 에 올렸다.
