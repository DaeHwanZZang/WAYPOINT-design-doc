## 발표 진행안

설계서 발표는 분량 제한이 없으므로 "전체 진행(약 40분)"을 기본으로 하고, 시간이 줄면 "핵심 진행(약 20분)"으로 줄인다. 어느 쪽이든 순서와 핵심 메시지는 같다. 쪽 번호는 설계서 v1.5 PDF 기준이며, 주석 본문의 각 쪽 왼쪽 그림과 같은 쪽이다.

### 핵심 메시지 세 문장 (처음과 끝에 반복)

- 병목(점유 존)만 관제하고 허가는 로봇이 보고한 위치를 증거로 내준다. 그래서 통신이 끊기거나 메시지가 사라져도 로봇은 멈출 뿐 충돌하지 않는다.
- AI 는 "예상 대기"라는 참고값만 비용에 더한다. 허가 규칙은 그대로이고, AI 가 없거나 틀려도 관제는 규칙으로 계속 돈다.
- 같은 맵·같은 대수·같은 주문에서 관제 방식만 바꾼 72회 실험으로 "규칙 대비 몇 %"를 숫자로 보인다.

### 발표 전 확인할 사실 (말하기 전에 직접 확인)

- 물리 통합 시험(`physics_test.py traffic`)을 발표 전에 한 번 돌려 결과를 확인한다. 돌리지 않았으면 "시험 시나리오가 있다"까지만 말한다(2장 주석).
- pytest 300개(2026-11-26 작업 트리, 수집 기준)와 코드 규모(표 10.2)는 발표 당일 다시 세어 숫자를 맞춘다.
- 와이어프레임·결과표 양식·model_card 예시 안의 숫자는 모두 예시다. "실측"처럼 읽지 않는다.
- 계획(주황) 항목은 "할 것"으로, 구현(파랑) 항목만 "되어 있다"로 말한다.

### 처음에 정의하고 시작할 용어 다섯 개

| 용어 | 한 줄 정의 |
|---|---|
| 점유 존 | 한 번에 한 대만 지나야 하는 구역(좁은 통로·교차로). 앞뒤에 대기 node 와 출구 node 를 둔다 |
| 통행권 (released) | 오더의 노드 중 "여기까지 가도 된다"는 표시. 허가 안 된 노드 앞에서 로봇은 스스로 멈춘다 |
| 예약 (lease) | FMS 장부에 적는 자원 점유. 통행권보다 먼저 저장하고 위치 증거로만 지운다 |
| 예약 수 규칙 | (대기열 + 예약된 통과 수) × 평균 통과 시간. AI 가 이겨야 하는 기준선 |
| 운행 (run) | 실험 1회(15분). run_id 로 이벤트·State·조건을 묶는다 |

## 장별 핵심 메시지와 연결

각 장을 한 문장으로 요약하고, 그 장이 다른 장과 어디서 이어지는지 적었다. 발표 중 "이건 어디에 있나"라는 질문에 이 표로 바로 쪽을 찾는다.

| 장 | 한 문장 | 이어지는 곳 |
|---|---|---|
| 1 개요 | 같은 조건에서 관제 방식만 바꿔 충돌·교착 0 과 대기 감소를 숫자로 보인다 | 완료 기준 → 9장 지표, 범위 → 부록 A.2 |
| 2 요구사항 | 모든 요구에 ID 를 붙여 화면·시퀀스·API·시험까지 추적한다 | 부록 A.1·A.2 추적표 |
| 3 데이터 | 배정 순간에 알던 값만으로 특징을 만들고 seed 단위로 나눈다 | 8.3 운행 폴더 사전, 4장 모델 |
| 4 AI | 규칙 기준선을 이겨야만 FMS 에 연결하고, 허가는 바꾸지 않는다 | 6.6.9 RouteCostPolicy, 7.4 ai_adapter |
| 5 화면 | 실제 캡처로 보이고, 이번 개발 화면은 기존 화면의 패널·탭으로 붙인다 | 표 5.3 → 8장 파일, 그림 5.2 흐름도 |
| 6 기능 | 다섯 개 안전 불변식 위에서 배정·허가·교착·장애 알고리즘을 정의했다 | 9.4 TC-T, 부록 A.4 |
| 7 API | 코드에서 자동 생성한 표로 인터페이스를 정의하고 역할 세 개로 권한을 나눈다 | 표 7.10 권한, 9.4 TC-X |
| 8 데이터 설계 | 현재 상태는 JSON, 이력은 SQLite, 예약은 TTL 없는 장부다 | 표 A.3 CRUD, 10.5 백업 |
| 9 지표·시험 | 72회 실험과 70개 시험 케이스로 요구를 검증한다 | 표 1.5 완료 기준, 부록 A.1 |
| 10 환경 | 서버 하나·브로커 하나로 배포하고, 외부에 열기 전 보안 점검표를 통과해야 한다 | 그림 10.1, 표 10.7 |
| 부록 | 제안서와 다른 점·발견한 위험·확인할 것을 숨기지 않고 남겼다 | A.2 · A.4 · A.5 |
