% 발표 주석 — 10장 개발환경구성

## 10 | 10장 개발환경구성
> FMS 는 Python·FastAPI, 로봇은 C++20·MuJoCo, 통신은 Mosquitto MQTT, 저장은 JSON + SQLite, 화면은 빌드 없는 HTML/JS, AI 는 scikit-learn(필요 시 PyTorch)입니다.

## 10.1 | 개발환경
> 기술 선택 기준은 "4주 안에 다섯 명이 바로 쓸 수 있고, 학교 서버 하나에 올릴 수 있는가"였습니다.

## 표 10.1 | 개발 환경
> 데이터베이스 서버, 프런트엔드 빌드 도구, 별도 추론 서버가 없는 구성입니다. 배포할 것은 FMS 프로세스 하나와 브로커 하나입니다.

- 로봇이 C++ 인 이유: 50ms tick 으로 물리(MuJoCo)·위치 추정·경로 계획을 돌리며 10대를 한 PC 에서 띄워야 한다.
- 실험 러너는 PyYAML·paho-mqtt·httpx·psutil 만 쓴다. psutil 로 CPU 사용률을 기록해 무효 운행을 판정한다.

## 표 10.2 | 현재 코드 규모
> 2026-11-26 작업 트리 기준 FMS·계약 Python 13.1k줄, 로봇 C++ 8.4k줄, 웹 화면 3.6k줄, pytest 300개입니다.

! 제안서의 "Python 9.4k · C++ 9.8k" 와 숫자가 다르다. 집계 시점과 범위가 다른 것으로 보이며(제안서 집계 기준은 기록이 없음), 발표에서는 이 표의 기준(`wc -l`, 테스트·외부 라이브러리 제외)을 밝히고 말한다. 질문이 오면 "제안서 이후 기능이 늘었고 집계 범위를 이번에 명확히 했다"고 답한다.

## 실행 명령 | 실행 명령
> 리포 두 개를 각각 루트에서 실행합니다. FMS 는 uvicorn 한 줄, 로봇은 make 후 robot_client, 통합 런처로 브로커·로봇 여러 대·뷰어를 한 번에 띄울 수 있습니다.

전체 pytest 가 약 7분 걸리는 이유: API 테스트마다 서버 수명 주기(스레드 종료)에 2~3초가 걸린다. 개발 중에는 바꾼 파일의 테스트만 돌린다.

## 표 10.3 | 주요 환경변수
> 브로커 주소, 데이터 폴더, 외부 접근 URL, STALE 판정 시간, 내장 승강기·자동문, 장애물·재경로, 이벤트 보존, 인증 설정입니다. v1.2 에서 keepalive·클라이언트 ID·브로커 필수 여부를 추가로 적었습니다.

- `FMS_PUBLIC_URL` 은 로봇이 맵을 받으러 오는 주소라, 로봇이 다른 PC 에 있으면 FMS PC 의 IP 로 바꿔야 한다. 시연 때 자주 틀리는 설정이다.
- `FMS_MQTT_CLIENT_ID`: 같은 브로커에 FMS 를 두 개 띄우면 같은 ID 끼리 서로 끊는다. 시험용 FMS 는 다른 ID·다른 브로커 포트를 쓴다.

## 10.2 | 소스디렉터리 구조
> 리포는 FMS(AMR-fms)와 로봇·도구(AMR-simulator) 두 개이고, 계약 원본은 AMR-fms 의 common/ 입니다.

트리에서 "(계획)" 표시가 이번 개발에서 생길 파일이다: `ai_adapter.py`, `runs.py`, `ai/` 학습 스크립트, `models/`, 러너 `run_experiment.py`, `experiments/` 시나리오. `planner.py` 는 지금 비어 있는 자리다.

## 10.3 | 명칭표준안
> 파일·클래스·함수·환경변수·REST 경로·JSON 필드·MQTT 토픽·이벤트·ID·테스트·브랜치·모델 이름 규칙을 한 표에 정리했습니다.

## 표 10.4 | 명칭 규칙
> 테스트 함수 이름은 한국어 동작 설명을 허용합니다. 예: test_출구_통과_전에는_해제하지_않는다.

- 클래스 이름 끝말로 역할을 구분한다: `*Store`(저장), `*Coordinator`/`*Controller`(조율), `*Error`/`*NotFound`/`*Conflict`(예외 → HTTP 422/404/409).
- 1초 루프에서 도는 함수는 `tick_*` 로 시작한다. 코드만 보고 어느 스레드에서 도는지 알 수 있다.
- 각도: API 의 theta 는 라디안, 웹 입력과 구역 회전은 도(°). 단위가 섞이는 유일한 곳이라 명시했다.

## 10.4 | 10.4 보안 설계 (v1.4 신설)
> 관제 서버의 가장 큰 위험은 정보 유출이 아니라 "누군가 로봇을 움직이거나 세우는 것"입니다. 그래서 쓰기 경로부터 막습니다.

## 그림 10.1 | 보안 경계
> 외부·서버·로봇 망 세 구역이고, 경계마다 API 키·브로커 계정·ACL·TLS·토큰을 둡니다.

## 표 10.5 | 위협과 통제 (STRIDE)
> 여섯 분류마다 이 시스템에서 실제로 가능한 위협을 적었습니다. 가장 위험한 것은 가짜 로봇이 State 를 보내 "존이 비었다"고 속이는 위장입니다.

가짜 State 위협이 중요한 이유: FMS 의 모든 허가는 State 를 증거로 쓴다. 증거를 위조할 수 있으면 안전 규칙 전체가 무력해진다. ACL 로 "로봇은 자기 ID 토픽에만 쓸 수 있다"를 강제하는 것이 핵심 통제다.

Q: 지금은 왜 익명 브로커를 쓰나?
A: 개발 편의 때문입니다. 배포 전 필수 항목으로 표 10.7 점검표에 넣었고, 하나라도 안 되어 있으면 외부에 열지 않는다는 규칙입니다.

## 10.5 | 10.5 배포·운영 절차
> 기동 순서, 배포 전 점검표, 백업·복구, 증상별 대응을 정했습니다.

## 표 10.6 | 기동·정지 순서
> 브로커 → FMS(worker 1) → 로봇 → 웹 순서이고, 정지는 현장 정지를 먼저 겁니다.

! uvicorn worker 를 2 이상으로 띄우면 파일 저장소·락 전제가 깨진다. 배포 스크립트에 1 을 고정한다.

## 표 10.7 | 배포 전 점검표
> 인증·토큰·외부 주소·브로커·데이터 폴더·클라이언트 ID·시뮬레이터·SSH 여덟 항목입니다.

`FMS_PUBLIC_URL` 이 틀리면 로봇이 맵을 못 받아 모든 작업이 "맵 동기화 대기"에 멈춘다. 배포 직후 가장 흔한 실수다.

## 백업 · 복구 | 백업과 복구
> 데이터 폴더 하나만 백업하면 됩니다. SQLite 는 .backup 명령으로, JSON 은 원자 교체라 그대로 복사합니다.

## 복구 후 반드시 확인할 것 | 복구 후 확인
> 백업 이후 로봇이 움직였으면 예약 장부와 실제 위치가 다를 수 있습니다. 위험하지는 않지만 "확인 필요" 존이 생기므로 복구 직후 교통 상태를 점검합니다.

## 표 10.8 | 증상별 대응
> 운영자가 화면에서 보는 증상 여덟 가지와 원인·조치입니다. 대부분은 대기 이유 문구가 원인을 그대로 말해 줍니다.

## +표 10.8 | 증상별 대응 (이어짐)
> 정체·연결 끊김·MQTT 끊김·승강기 확인 필요·AI 대체 증가에 대한 조치입니다. 공통 원칙은 "존 안 로봇은 건드리지 않고, 위치를 확인한 뒤 정리한다"입니다.

## 10 | 심화 질의응답 — 환경·보안
Q: 학교 AWS 를 못 쓰면 시연은 어떻게 하나?
A: 로컬 PC 에서 브로커·FMS·로봇을 모두 띄워 시연하고, 72회 실험은 팀원 PC 에서 돌립니다. 배포 환경은 결과물의 필수 조건이 아니라 확인 필요 항목(부록 A.5)입니다.
Q: 개인 키나 비밀번호가 리포에 들어갈 위험은?
A: API 키는 해시로만 저장하고, 브로커 비밀번호 파일과 인증서는 데이터 폴더·서버에만 두며 리포에 올리지 않습니다(.gitignore). 설정 예시는 값 없이 키 이름만 둡니다.
