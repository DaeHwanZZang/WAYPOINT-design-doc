## 문서 정보 | 표지와 문서 정보 — 이 문서가 무엇인가
> 이 문서는 제안서 v1.2 에서 약속한 FMS 를 "무엇을, 어떤 구조로, 어떻게 검증하며" 만들지 정한 설계서입니다. 이미 구현된 부분은 실제 코드 그대로, 이번 4주 개발분은 주황색 "계획"으로 구분해 적었습니다.

발표 첫 장에서는 세 가지만 짚는다.
- **기준 문서**: 제안서 v1.2(11/25)와 실제 코드(AMR-fms, AMR-simulator). 설계서가 코드보다 앞서 나간 부분은 모두 "계획" 배지를 달았다. 교수님이 "이거 진짜 있냐"고 물으면 배지 색으로 바로 답할 수 있다.
- **표기 규칙**: 파랑 = 구현(2026-11-25 코드에 있음), 주황 = 이번 개발(12/09 기능 동결까지), 노랑 = 일부만, 회색 = 범위 밖. 그림 색도 같은 규칙이다.
- **변경 이력**: v1.0(10/28)은 미션·재고·React·MySQL·GCP·LLM Copilot 기준이었다. 제안서가 v1.2 로 바뀌면서 관제 방식(점유 존)·범위·AI 대상이 모두 달라져 v1.1 에서 본문을 전부 다시 썼고, v1.2 부터는 검수·보강 단계다.

Q: v1.0 과 비교해 무엇이 제일 크게 바뀌었나?
A: 관제 방식입니다. v1.0 은 모든 통로를 그래프로 그리고 초 단위 시간창을 예약하는 방식이었는데, 지연·통신 끊김에 약하고 현장마다 그래프를 그려야 했습니다. 지금은 병목(점유 존)만 관제하고 그 사이 주행은 로봇이 스스로 A* 로 갑니다. 자세한 비교는 부록 A.3 표에 있습니다.

Q: 왜 hwp 가 아니라 PDF 인가?
A: 설계서를 HTML 소스로 관리해 코드에서 API 표·스키마 표를 자동 생성하기 때문입니다. 제출 형식은 교수님 확인 사항으로 부록 A.5 에 올려 두었습니다.

## 표 0.1 | 변경 이력
> 버전마다 무엇을 바꿨는지 한 줄씩 남깁니다. v1.1 은 전면 개정, v1.2 이후는 검수와 상세화입니다.

v1.1 의 ①~⑧ 항목은 발표에서 하나씩 읽지 말고 "관제 방식, 범위, 기술 스택, AI, 일정, 실험, 추가 구현, 화면" 여덟 덩어리로만 말한다. v1.2 이후 행은 무엇을 보강했는지(목차 쪽번호, 그림·표 목차, 코드 대조 수정, 발표 주석)를 말하면 된다.

! "전면 개정"이라고 말할 때 v1.0 을 버린 이유(제안서 v1.2 와 코드가 달라짐)를 같이 말해야 성의 없어 보이지 않는다.

## 표 0.2 | 작성·검토 분담
> 장마다 작성자와 검토자를 다르게 두었습니다. 쓴 사람이 자기 글을 검토하지 않게 했습니다.

담당은 1.3절 R&R 과 같은 축이다. AI 장(3·4·9)은 데이터·AI 담당 세 명이 나눠 쓰고 팀장이 검토, 화면 장은 웹 담당이 쓰고 배정·백엔드 담당이 검토한다. 화면이 부르는 API 를 그 API 담당이 확인하도록 짝을 지은 것이다.

## 목 차 | 목차
> 학과 설계서 양식의 장 구성(1 개요 ~ 10 개발환경)을 그대로 따르고, 추적성·제안서 대조·위험은 부록으로 뺐습니다.

목차 쪽번호는 빌드할 때 PDF 에서 실제 쪽을 찾아 채운다(손으로 적지 않음). 발표에서 목차는 10초 안에 넘기고 "핵심은 6장(기능 설계)과 9장(실험 설계)"이라고만 말한다.

Q: 장 구성이 양식과 다른 곳이 있나?
A: 없습니다. 양식 장 번호를 유지하고, 양식에 없는 내용(교착·장애 같은 설계 결정, 제안서 대조)은 상자나 부록으로 덧붙였습니다.

## 그림 목차 | 그림 목차
> 그림은 57개입니다. 시퀀스 22종, 유스케이스 3종, 상태도 3종, ERD, 간트, 실제 화면 캡처 17장이 주입니다.

다이어그램은 전부 코드(`tools/make_diagrams.py`)로 그린 SVG 라 문서와 설계가 같이 고쳐진다. 화면 그림은 실제 FMS 에 시뮬레이터 로봇 4대를 붙여 찍은 것이다(가짜 목업이 아님).

## 표 목차 | 표 목차
> 표는 90개가 넘습니다. 요구사항 ID·화면 ID·시퀀스 ID·API ID 로 서로 연결되고, 연결은 부록 A.1 추적성 매트릭스에서 한 번에 봅니다.

REST API 상세표(7.3)와 MQTT 메시지 표(7.1)는 FMS 코드에서 자동 생성한 것이라 손으로 옮겨 적은 오타가 없다. 코드가 바뀌면 다시 뽑는다(README 의 명령).

## 표지 | 표지
> 3팀 WAYPOINT 의 "다중 AMR 로봇의 작업 할당 및 트래픽 제어를 위한 FMS" 설계서입니다. 점유 존 통행 허가와 AI 혼잡 예측으로 여러 대의 로봇이 충돌·교착 없이 더 많은 일을 하게 만드는 중앙 관제 시스템입니다.

표지에서 할 말은 팀 소개와 한 문장 요약이다. 역할 분담(팀장 김대환 PM·FMS 코어·시뮬레이터, 김민준 배정·충전·백엔드·배터리 예측, 최민석 실험·뷰어·이상 탐지, 박시현 웹 관제·시연 화면, 안태현 데이터·혼잡 예측·인프라)을 한 번에 소개하고, 개발 기간(11/24~12/18)과 평가발표회(12/16)를 말한다.

! 발표 시간 배분 제안: 1장 개요 10%, 2장 요구사항 10%, 3·4장 데이터·AI 20%, 5장 화면 15%, 6장 기능 설계 25%, 7~10장 15%, 부록 A.2·A.5 5%.
